# Vascular trees in Julia

`VascularTrees.jl` is a Julia package for processing synthetic vascular networks of the
liver and for building and simulating pharmacokinetic computational models on these
graphs. The vascular trees are generated with
[SyntheticVascularTrees.jl](https://gitlab.com/etiennejessen/SyntheticVascularTrees.jl);
this package converts them into an efficient tabular format and runs coupled ODE
simulations of substance transport along the trees.

The corresponding Python code is located at
https://github.com/matthiaskoenig/vascular_trees.

## Features

- **Tree processing** ([src/build_arrow_graphs.jl](src/build_arrow_graphs.jl),
  [src/trees_processing/](src/trees_processing/)): converts graphs generated by
  SyntheticVascularTrees.jl (`.lg` edge lists + node/edge attribute CSVs) into `.arrow`
  tables — one table per vascular tree (ODE groups, ids, flows, volumes, ...) and a
  `T.arrow` table for the terminal nodes connecting the trees.
- **Simulation** ([src/run_simulations.jl](src/run_simulations.jl),
  [src/simulation/](src/simulation/), [src/models/](src/models/)): coupled
  pharmacokinetic ODE simulations of drug transport along the liver's vessel trees —
  from the inflow trees (arterial, portal) through the liver sinusoids (terminal part)
  to the outflow trees (venous, biliary) — with optional benchmarking of running times.
- **Visualization** ([old/visualization/](old/visualization/)): plots of benchmarking
  results (Makie / AlgebraOfGraphics) and mapping of simulation results back onto the
  VTK geometry of the trees. *Note: this part is not yet part of the package; it is kept
  in `old/` until it is refactored to the new module structure.*

### Supported tree configurations

| Configuration      | Inflow trees | Outflow trees |
|:-------------------|:-------------|:--------------|
| `"Rectangle_trio"` | `A`, `P`     | `V`           |
| `"Rectangle_quad"` | `A`, `P`     | `V`, `B`      |

(`A` = arterial, `P` = portal, `V` = venous, `B` = biliary. Defined in
[src/common/definitions.jl](src/common/definitions.jl).)

## Repository structure

```
src/
├── VascularTrees.jl          # main module
├── build_arrow_graphs.jl     # run script: convert generated trees to .arrow tables
├── run_simulations.jl        # run script: coupled-tree simulations
├── common/                   # paths, tree definitions, option structs, table utilities
├── trees_processing/         # reading and processing of the generated tree files
├── models/                   # pharmacokinetic ODE models, Jacobians and interventions
│   └── equations/            # ODE right-hand sides of the trees and the terminal part
└── simulation/               # simulation module
    ├── setup/                # ODE parameters and problems
    ├── solver/               # time loop and coupling of the trees
    └── results/              # saving of solutions and benchmarking
sbml/                         # test scripts for importing SBML models
old/                          # legacy code (incl. visualization, not yet refactored)
```

## Results folder structure

**Important:** the run scripts do *not* create any folders themselves — they read from
and write into an existing directory layout under `results/`. Before running, make sure
the following structure exists for every tree configuration and number of nodes you want
to process:

```
results/
└── julia_vessel_trees/
    ├── jrunning_times.csv                   # benchmark running times (written by run_simulations.jl)
    └── <tree_configuration>/                # e.g. Rectangle_quad
        └── <tree_configuration>_<n_nodes>/  # graph directory, e.g. Rectangle_quad_100
            ├── julia/                       # INPUT: trees generated by SyntheticVascularTrees.jl
            │   ├── <tree>.lg                #   edge list (graph skeleton)
            │   ├── <tree>_edges.csv         #   edge attributes
            │   ├── <tree>_nodes.csv         #   node attributes
            │   └── <tree>.vtk               #   geometry (used for visualization)
            ├── graphs/                      # OUTPUT of build_arrow_graphs.jl
            │   ├── <tree>.arrow             #   one table per vascular tree
            │   └── T.arrow                  #   terminal nodes connecting the trees
            ├── simulations/                 # OUTPUT of run_simulations.jl
            │   └── <tree>[_<f>Q]_simulations_<dt>_dt.arrow
            └── models/                      # currently not used by the Julia code
```

where `<tree>` is one of the vascular trees of the configuration (`A`, `P`, `V`, `B`)
plus `T` for the terminal part, and `_<f>Q` appears in the file name only if the flow
scaling factor `f` differs from `1.0`.

# Usage

## 1. Generate vascular trees

Generate the synthetic vascular trees with
[SyntheticVascularTrees.jl](https://gitlab.com/etiennejessen/SyntheticVascularTrees.jl)
(see [Installation](#installation)). For each vascular tree (e.g. `A`, `P`, `V`, `B`)
three files are expected in the `julia/` subfolder of the graph directory:

- `<tree>.lg` — edge list (graph skeleton)
- `<tree>_edges.csv` — edge attributes
- `<tree>_nodes.csv` — node attributes

## 2. Build arrow graphs

```bash
julia --project src/build_arrow_graphs.jl
```

Processing starts as soon as the file is included. Which trees are processed is set in
the `TreeOptions` struct inside the script (`n_nodes` and `tree_configurations`). The
resulting `.arrow` tables are written to the `graphs/` subfolder of the graph directory.

## 3. Run simulations

```bash
julia --project src/run_simulations.jl
```

The simulations start as soon as the file is included, using the options defined in the
script:

- `TreeOptions` — which tree configurations and numbers of nodes to simulate
  (every combination is run).
- `SimulationOptions` — time span `tspan` [min], number of `steps`, whether to save the
  solutions (`save_simulations`) and whether to benchmark (`benchmark`).
- `SolverOptions` — ODE solver (any
  [SciML algorithm](https://docs.sciml.ai/DiffEqDocs/stable/solvers/ode_solve/), e.g.
  `Tsit5()` or `CVODE_BDF()`), its tolerances and whether to use the analytic Jacobian
  (`compute_jacobian`, default `true`). The Jacobian is sparse, so with CVODE use a sparse
  linear solver: `CVODE_BDF(linear_solver = :KLU)` (the default solver). KLU requires
  `compute_jacobian = true`; this is checked when `SolverOptions` is constructed.
- `BenchmarkOptions` — number of timed iterations and whether to save the running times
  (used only if `benchmark = true`).
- `flow_scaling_factors` — factors by which the flow is scaled (`1.0` = original flow).

Outputs (in the graph directory):

- `simulations/<subsystem>_simulations_<dt>_dt.arrow` — one file per vascular tree and one
  for the terminal part (if `save_simulations = true` and benchmarking is off). Each table
  has one row per species: a `species_ids` column followed by one column per time point
  (`t_<time>`).
- `results/julia_vessel_trees/jrunning_times.csv` — benchmark running times (if
  `benchmark = true` and `save_running_times = true`).

# Installation

## Requirements

- [Julia](https://julialang.org/) ≥ 1.13
- Optional: [Visual Studio Code](https://code.visualstudio.com/) with the
  [Julia extension](https://www.julia-vscode.org/)

## Clone the repository

```bash
git clone https://github.com/matthiaskoenig/vascular_trees.jl.git
cd vascular_trees.jl
```

## Install SyntheticVascularTrees.jl

This package depends on the
[SyntheticVascularTrees.jl](https://gitlab.com/etiennejessen/SyntheticVascularTrees.jl)
package developed by Etienne Jessen and
[Dominik Schillinger](https://www.bauing.tu-darmstadt.de/fachbereich_bau_umwelt/ueber_den_fachbereich/professoren____innen_am_fb/professorenliste_details_115392.de.jsp)
at the TU Darmstadt for generating the vascular trees.

- clone the repository and open a terminal in `SyntheticVascularTrees.jl`
- start `julia`, enter the package mode with `]`, then:
  `activate .` → `build` → `test`
- choose the Julia environment in Visual Studio Code

## Install dependencies

All dependencies of this package are specified in `Project.toml` / `Manifest.toml` and
are installed with:

```bash
julia --project -e "import Pkg; Pkg.instantiate()"
```

# Environment activation

## Activate the project

Either start Julia with the project flag from the repository root:

```bash
julia --project=.
```

or activate the environment from the Julia package mode:

```julia
julia> ]
pkg> activate .
```

In Visual Studio Code, select the environment via the command palette
(`Julia: Change Current Environment`) or the environment indicator in the status bar.

## Multithreading

To allow Julia to use multiple threads, set the `JULIA_NUM_THREADS` environment
variable, e.g.:

```bash
JULIA_NUM_THREADS=auto julia --project=.
```

or equivalently start Julia with `julia --threads auto`. In Visual Studio Code this can
be configured in `settings.json`:

```json
"julia.NumThreads": "auto"
```
